# C Checker — проверка C-проектов

**C Checker** — Bash-скрипт для автоматизации проверки исходного кода на C в рамках обучения в «Школе 21».

Программа объединяет инструменты статического анализа, проверки форматирования, компиляции и выполнения программы, а также обнаружения ошибок управления памятью. Поддерживает интерактивное меню и запуск отдельных проверок через командную строку.

## Возможности

- **Проверка форматирования** — анализ исходного кода с помощью `clang-format`.
- **Автоформатирование** — исправление форматирования файлов с помощью `clang-format -i`.
- **Статический анализ** — поиск потенциальных ошибок и проблем в коде с помощью `cppcheck`.
- **Компиляция** — сборка программы с предупреждениями `-Wall`, `-Wextra`, `-Werror` и стандартом C11.
- **Запуск программы** — выполнение собранного бинарного файла с ограничением времени.
- **Проверка памяти** — обнаружение проблем с памятью с помощью Valgrind в Linux или `leaks` в macOS.
- **AddressSanitizer** — дополнительная проверка ошибок работы с памятью.
- **Проверка Makefile** — проверка наличия и доступности целей `all`, `clean`, `rebuild` и `test`.
- **Диагностика окружения** — проверка доступности необходимых инструментов.

При выполнении комплексного тестирования скрипт прекращает последовательность проверок при обнаружении ошибки на критическом этапе.

## Используемые инструменты

| Инструмент | Назначение |
|---|---|
| Bash | Автоматизация проверок |
| clang-format | Проверка и исправление форматирования |
| cppcheck | Статический анализ исходного кода |
| GCC / G++ | Компиляция |
| Valgrind | Анализ ошибок работы с памятью в Linux |
| AddressSanitizer | Обнаружение ошибок памяти во время выполнения |
| Make | Работа с Makefile |

## Требования

Для работы в Ubuntu необходимо установить инструменты:

```bash
sudo apt update
sudo apt install build-essential clang-format cppcheck valgrind make
```

Для ограничения времени выполнения используется `timeout`. При необходимости установи пакет `coreutils`:

```bash
sudo apt install coreutils
```

Скрипт также содержит поддержку некоторых инструментов macOS, но основное целевое окружение проекта — Linux.

## Использование

### Интерактивное меню

Запусти скрипт без аргументов:

```bash
./ccheck.sh
```

Откроется меню со следующими действиями:

| Пункт | Действие |
|---:|---|
| 1 | Полное тестирование |
| 2 | Форматирование и статический анализ |
| 3 | Только проверка форматирования |
| 4 | Только `cppcheck` |
| 5 | Компиляция и запуск |
| 6 | Компиляция и запуск с AddressSanitizer |
| 7 | Проверка памяти |
| 8 | Автоформатирование исходников |
| 9 | Проверка Makefile |
| 10 | Диагностика окружения |
| 0 | Выход |

### Запуск отдельной проверки

Можно передать номер действия и путь к файлу или каталогу:

```bash
./ccheck.sh 3 src/pong.c
```

Проверить форматирование файла.

```bash
./ccheck.sh 4 src
```

Выполнить статический анализ исходников в каталоге `src`.

```bash
./ccheck.sh 8 src/pong.c
```

Применить форматирование к файлу `src/pong.c`.

```bash
./ccheck.sh 5 src/pong.c
```

Скомпилировать и запустить программу, собранную из указанного исходника.

Для комплексной проверки:

```bash
./ccheck.sh 1 src/pong.c
```

**Важно:** при запуске программы скрипт передаёт ей пустой ввод (`stdin`). Если программа ожидает пользовательский ввод, она может завершиться раньше времени или получить `EOF`. Для полноценной проверки интерактивных программ необходимо предусмотреть подачу тестовых данных.

## Режимы проверки

### Форматирование

Скрипт использует `clang-format` и конфигурацию `.clang-format`. Если конфигурация отсутствует, создаётся новая. Существующий конфигурационный файл не перезаписывается.

Проверка форматирования не изменяет исходники. Автоформатирование применяется отдельно.

### Статический анализ

Для `cppcheck` используются параметры:

```bash
cppcheck \
    --enable=all \
    --suppress=missingIncludeSystem \
    --error-exitcode=1 \
    --inline-suppr \
    --suppress=normalCheckLevelMaxBranches \
    src/
```

В обычном режиме дополнительно подавляются некоторые диагностические сообщения. Это не заменяет ручной разбор предупреждений анализатора.

### Компиляция

Для программ на C используются основные флаги:

```bash
gcc -Wall -Werror -Wextra -std=c11 -g
```

При необходимости можно передать дополнительные параметры компиляции через переменные окружения.

### Проверка памяти

В Linux используется Valgrind с анализатором `memcheck`. В macOS предусмотрен запуск `leaks`.

AddressSanitizer запускается отдельно, поскольку его совместное использование с Valgrind или некоторыми режимами `leaks` может приводить к конфликтам.

## Настройка через переменные окружения

| Переменная | Назначение |
|---|---|
| `CCHECK_SOURCE` | Исходный файл или каталог. По умолчанию `.` |
| `CCHECK_BINARY` | Имя выходного бинарного файла. По умолчанию `./main.out` |
| `CCHECK_BUILD_CMD` | Пользовательская команда сборки |
| `CCHECK_CFLAGS` | Дополнительные флаги компилятора |
| `CCHECK_RUN_ARGS` | Аргументы запуска программы |
| `CCHECK_TIMEOUT` | Лимит времени выполнения в секундах. По умолчанию `60` |
| `CCHECK_STYLE` | Стиль форматирования: `google` или `custom` |
| `CCHECK_CPPCHECK_STRICT` | Значение `1` включает более строгий режим подавления предупреждений |
| `CCHECK_LEAKS_MODE` | Режим проверки памяти в macOS: `atexit` или `dylib` |

Пример запуска с дополнительными флагами:

```bash
CCHECK_TIMEOUT=30 \
CCHECK_CFLAGS="-lm" \
./ccheck.sh 5 src/pong.c
```

## Ограничения

- Скрипт не заменяет тесты с заранее определёнными входными и ожидаемыми выходными данными.
- Если проект состоит из нескольких независимых программ с отдельными функциями `main()`, их нельзя без изменений объединить в одну сборку. В таком случае следует проверять каждую программу отдельно.
- Для программ, требующих пользовательского ввода, нужно организовать подачу тестовых данных.
- Наличие предупреждений анализатора не всегда означает ошибку выполнения, но каждое предупреждение следует проверить.
- Для работы режимов используются внешние инструменты, которые должны быть установлены в системе.

## Назначение проекта

Проект создан для упрощения локальной проверки учебных заданий на C, сокращения количества ручных команд и раннего обнаружения ошибок перед отправкой решения в GitLab.

C Checker объединяет типовые этапы проверки в одном скрипте и позволяет запускать как комплексное тестирование, так и отдельные инструменты по необходимости.
